# 사례 연구: Prompt v5 후보가 비용은 줄였지만 자동 판정이 후퇴해 승격을 보류한 일

**결정: 승격 보류(DISCARD) · 측정 기록과 규칙 분리 구조는 보존 · 운영 기본값은 바뀌지 않음**

조건: 2026-10-02, Gemini 3.5 Flash-Lite, Skill v6.1 고정, 합성 입력 30건(정상 12·경계 10·실패 유도 8) 1회씩, 최대 출력 2,048 tokens. **Prompt만 바꿨습니다.** v4 `coaching-user-supplied-v4-verification` → v5 후보 `coaching-v5-skill-owned`.

| 지표 | v4 | v5 후보 | 변화 |
| --- | --- | --- | --- |
| 출력 계약 통과 | 30/30 | 30/30 | 같음 |
| 종합 자동 통과 | 22/30 | 20/30 | 2건 감소 |
| 기대 판정 일치(intent·C/A/V × 30건) | 116/120 | 107/120 | 9개 감소 |
| 지원 문장 근거 | 63/63 | 58/61 | 분모가 다름(적용 가능한 검사 수) |
| 응답 시간 p50 / p95(초) | 3.847 / 4.621 | 3.939 / 4.622 | p50 약 +0.09, p95는 거의 같음 |
| 비용(30건, USD) | 0.19638110 | 0.17027067 | 약 13.3% 감소 |

종합 자동 통과는 출력 계약, 적용 가능한 모든 판정, 지원 문장 근거, 질문·행동 대상 검사를 **모두** 충족한 케이스입니다. 코칭 자유서술의 사람 품질 점수가 아닙니다. 계약 통과(30/30)는 JSON 형식 적합성이라 품질 지표로 읽으면 안 됩니다.

회귀한 문항은 normal-09·10, boundary-13·20(통과→실패)이고, normal-07·failure-23은 실패→통과였습니다.

## 결정

비용은 약 13.3% 낮아졌지만 자동 통과와 기대 판정이 줄어, 품질 개선 후보로의 승격은 보류했습니다. 10/2 후보의 측정 기록과 규칙 분리 구조는 남겼고, 운영 기본값을 되돌리거나 바꾼 결정은 아닙니다.

## 한계

- 각 Prompt를 **1회**씩만 실행했고 실행 순서와 캐시는 통제하지 않았습니다. 이 비교에서는 사람 검토가 없어 원인을 확정할 수 없습니다.
- 2,048 tokens 설정에서 JSON이 잘린 출력이 1건 있었습니다. 같은 후보를 4,096 tokens로 다시 돌렸을 때도 계약은 30/30이었지만, 이 품질 비교를 대체하지는 않습니다.
- 원시 결과는 Git에서 제외했고 집계 스크립트도 저장소에 없어서, 같은 숫자를 그대로 다시 만들 수 있다고 말할 수 없습니다.
